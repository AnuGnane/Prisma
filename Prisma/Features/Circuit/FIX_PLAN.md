# Circuit — Fix Plan (Apr 2026)

Companion to `GRID_DESIGN.md`. Captures the two bugs identified in the end-to-end audit, the chosen remediation, and the test coverage that locks the fix in. Keep this file until the next Circuit audit lands.

## Bug 1 — "Your Game" board state isn't saving properly

**Symptom.** On restoring a saved Circuit game, paths render in seemingly random order; synth-bearing boards frequently restore to a non-winning visual even when the player saved mid-game.

**Root cause.** `CircuitState.activePaths` was serialized as a Swift `Dictionary`. Swift dictionaries do not preserve insertion order, so draw order was lost on save. The restore path compensated with a permutation search that replayed every ordering and accepted the first **winning** terminal state. For canonical solutions this worked; for saves that captured a losing, mid-game, or give-up state, the permutation search found no winner and fell back to a deterministic alphabetical-by-color replay — which, in any level with a synth, routes inputs in the wrong order and produces garbage visuals.

Synth behavior is order-sensitive by design: the first input to arrive is held as `.partiallyFilled`; the second triggers the merged output. Swap order and the partial contributor becomes the output carrier.

**Fix.** Treat draw order as first-class save state.

1. Added `pathOrder: [NeonColor]?` to `CircuitState` (`CircuitStateSerializer.swift`), optional for back-compat.
2. ViewModel tracks `drawnColorOrder: [NeonColor]` — appended on `startNewPath`, pruned on `clearPath`, reset on `reset` and `resetRuntimeStateForRestore`.
3. `buildGameResult(...)` now passes `pathOrder: drawnColorOrder` to the serializer.
4. `restoreState(_:)` honors `state.pathOrder` verbatim when present. Falls back to permutation search only when `pathOrder == nil` (legacy saves + canonical `solutionStateJSON`) — preserving legacy behavior without introducing new ambiguity.
5. Corrupt `pathOrder` entries (colors not present in `activePaths`) are silently filtered during decode.
6. `NeonColor.init(legacyRawValue:)` extracted from `init(from:)` so `pathOrder` decoding also migrates legacy color names (`cyan`, `magenta`, `amber`, `violet`, `coral`).

**Trade-offs.**

- New field is additive and optional, so existing persisted saves keep working.
- Canonical `solutionStateJSON` entries were upgraded to include `pathOrder` during the level redesign (below); older curated solutions without `pathOrder` still load via the permutation fallback.
- `drawnColorOrder` is ViewModel state, not persisted separately — it is always derived from user input or restored from save. No new SwiftData migration needed.

## Bug 2 — Unwinnable curated levels (L6, L10, L16, L20, L21, L25)

**Symptom.** Six curated levels could never be beaten. L6 and L10 showed the wrong pair-color in the HUD; L16, L20, L21, L25 had synth targets that no legal mix could produce.

**Root cause, group A (L6, L10).** The terminal-pair `color` metadata said `"blue"` but the target cell was purple. Since the win check compares against the target **cell**, the level was in fact solvable — but the HUD read from `pair.color`, telling players to deliver blue to a purple target. A drift-class bug: target cells were updated during a prior redesign; pair metadata wasn't.

**Fix A.** Updated `pair.color` in `circuit_levels.json` to `"purple"` for L6 and L10 to match the target cell.

**Root cause, group B (L16, L20, L21, L25).** Each level routed a green path and an orange path (or equivalent "two secondaries that span all three primary channels") into a synthesizer whose output was a primary color. `NeonColor.mixed(with:)` builds the union of primary channels across both operands; when the union equals `{blue, red, yellow}` — the tertiary case — it returns `self` unchanged. So the synth output never matched the primary target, and no permutation of inputs could win.

See `GRID_DESIGN.md` §2 ("tertiary trap") for the general rule.

**Fix B.** Redesigned all four levels with primary+primary → secondary mixes:

| Level | New scheme                                           |
|-------|------------------------------------------------------|
| L16   | 5×5 intro synth. blue + red → purple target.         |
| L20   | 6×6 synth + bridge. red + yellow → orange target.    |
| L21   | 5×5 blue + yellow → green target.                    |
| L25   | 6×6 capstone. XOR synth + directional NOT. blue (NOT-inverted to inactive) XOR red/active → active output; blue+red → purple at mix. Without the NOT the XOR would kill the active signal, making the gate genuinely load-bearing. |

New grids, solution paths, and `solutionStateJSON` (including `pathOrder`) were generated by `scratch/redesign_levels.py` and spliced into `Resources/circuit_levels.json`. `CircuitLevelLoaderTests.allCuratedSolutionsReplayToSolvedState()` replays each curated solution and asserts a winning state — all 25 levels pass.

## Test coverage added

Locked into `PrismaTests/CircuitGameTests.swift`:

- `CircuitColorMixingTests.tertiaryMixesReturnReceiver()` — pins the tertiary-trap behavior so no future edit accidentally "fixes" it and silently breaks level intent.
- `CircuitColorMixingTests.secondaryMixWithMissingPrimaryReturnsReceiver()` — negative case for the illegal secondary+completing-primary mixes.
- `CircuitSerializationTests.pathOrderRoundTrip()` — save+restore preserves `drawnColorOrder`.
- `CircuitSerializationTests.corruptedPathOrderFiltersGhosts()` — malformed saves don't crash or inject phantom paths.
- `CircuitSerializationTests.legacyColorDecoding()` — confirms `pathOrder` is `nil` on pre-fix saves so restore falls back to permutation search.
- `CircuitLevelLoaderTests.terminalPairColorMatchesTargetCell()` — structural check that prevents L6/L10 drift recurring for any level.
- `CircuitLevelLoaderTests.allCuratedSolutionsReplayToSolvedState()` — unchanged in intent, now exercises the redesigned L16/L20/L21/L25.
- `CircuitDrawOrderFidelityTests.drawnColorOrderPersistsThroughSaveAndRestore()` — ViewModel-level save/restore proves draw order survives round-trip.
- `CircuitDrawOrderFidelityTests.synthDrawOrderSurvivesRoundTrip()` — restores a synth board and verifies the first-arriving contributor remains the partial input.
- `CircuitDrawOrderFidelityTests.nonWinningSnapshotReplaysFaithfully()` — the original symptom: mid-game saves now restore visually identically.

## Rollout

1. `BuildProject` on `windowtab1` — passes (0.37s, no warnings above baseline).
2. `RunSomeTests` on the four Circuit suites above — all 22 executed tests pass. (The MCP tool's output-schema validator rejects the aggregate response because the server omits the empty `errors: []` field on successful results; the individual test outcomes are unaffected.)
3. Manual smoke on device is recommended before shipping: open any mid-game save on L20 or L25, verify the rendered grid matches what was saved.

## Follow-ups (not in scope for this fix)

- `scratch/redesign_levels.py` should be migrated into the main project or promoted to a real CI audit. Currently a throwaway.
- Curated `solutionStateJSON` for older single-path levels does not include `pathOrder` — this is fine (they fall through to permutation search) but adding `pathOrder` across the catalog would let us remove the permutation fallback in a future cleanup.
- Consider a per-level schema validator that runs at load time in debug builds and `fatalError`s on a §6 checklist violation, so authoring mistakes surface immediately instead of shipping to players.
